# GhostForge code map

Use this file to locate code before searching. Line numbers are approximate and may drift; prefer symbol/route names.

## Backend entry point: `ghostforge-server.js`

### Shared/local-system endpoints
- `GET /health` — basic backend health.
- `GET /api/gemini-keys` / `POST /api/gemini-keys` — persistent Gemini accounts + model in `uploads/gemini-keys.json` (`server/gemini-secrets.js`, `GHOSTFORGE_SECRETS_FILE` to relocate). Written on every UI change; secrets are never logged.
- `GET /api/pgd-status` — checks Python/OpenCLIP/CUDA readiness.
- `GET /api/encoders` — probes CPU/NVIDIA/Intel FFmpeg encoders.
- `/api/save-dir`, `/api/pick-videos`, `/api/pick-folder`, `/api/export-copy`, `/api/open-folder` — local filesystem UX. `POST /api/export-copy` takes `existingDest`. `server/export-copy.js` (`planExportCopy`) skips the copy when that file is still inside the destination folder, and writes the requested name again when it was deleted. A different file with the same name still becomes `name (1).ext`. Optional `groupFolder` is the source video name: `videoGroupFolder` / `exportDirForGroup` make one subfolder under the chosen path and the copy goes there. The subfolder is created only after the output file is found. A failed copy returns `folder` and the error text. If `jobs` no longer has that id, `heldOutputPath` still accepts `uploads/<16-or-32-hex>_output.mp4`. The Edit cut list still has Save all into the shared folder with no subfolder. The per-video row shows the folder path and opens it after a successful copy.

### YouTube import (source file only)
Paste video URLs into a client queue. The server still downloads one video at a time. The original mp4 is copied into the folder chosen when that URL was added. Unique, Edit, or Reframe receive it only when that destination is selected. It is not a fourth pipeline and does not change those filters.
- `GET /api/youtube-import/status` — yt-dlp/ffmpeg readiness. `?fresh=1` bypasses the 60s cache.
- `POST /api/youtube-import` — body `{ url, quality, tab }` where `quality` is `best` or a ceiling of `144`, `240`, `360`, `480`, `720`, `1080` (default), `1440`, `2160`, or `4320`. The ceiling is yt-dlp `res:` (the shorter side), so a 1080p Short is 1080×1920. `tab` is `save`, `unique`, `edit`, or `reframe`. Optional `channelKey` stays on the job and is absent from the 201 body. One import at a time.
- `GET /api/youtube-import/stream/:jobId` — SSE for that import. Do not open it on `GET /api/stream/:jobId` (`uniqueStreamBlock` rejects `kind: 'youtube-import'`).
- `POST /api/youtube-import/:jobId/save` — copies that import mp4 into `{ path }`. The server chooses the filename. A destination inside `uploads/youtube-import` is rejected. `removeSource: true` deletes the import directory only after the copy succeeds. This is allowed as soon as the mp4 is registered, including the moment before the stream closes. `DELETE` stays 409 until the stream finishes, so a save-only download must not call DELETE to drop the source. Optional `channelKey` (`UCxxxx:videos` or `UCxxxx:shorts`) records that video id and moves that tab's anchor. A save with no key still records the id. A failed copy records nothing on this route. A successful copy also writes `uploads/youtube-receipts.json`.
- `DELETE /api/youtube-import/:jobId` — removes that import directory. Edit success does not call it; Unique and Reframe do, after the pipeline has closed the file. Save-only does not call it.
- `POST /api/youtube-import/hold` — body `{ path }`. Copies an mp4 that already sits outside `uploads/youtube-import` into `uploads/youtube-import/<jobId>/`. Unique and Reframe then delete that copy. The file in the channel folder stays. No yt-dlp, no ledger row, and no receipt.
- `GET /api/youtube-channels` — channel rows (title, tab, folder, anchor, saved count). It does not return every downloaded id.
- `POST /api/youtube-channels/scan` — body `{ url, sharedFolder }`. Reads one tab with `yt-dlp --flat-playlist` (no `--no-playlist`) and does not take the single import slot. `/shorts` is the Shorts tab, `/videos` is the Videos tab, and a channel home is Videos. The same channel's two tabs are two rows. Playlists stay rejected. `local` is the newest-first list of videos that are inside the 1000-entry window and already an mp4 in the channel folder or the shared folder, capped at 40. The client does not receive filesystem paths. A file older than that window has no number until a scan includes it.
- `POST /api/youtube-channels/:key/folder` — body `{ path }`. Empty path uses the shared YouTube folder. A path must be an existing directory outside `uploads/youtube-import`.
- `POST /api/youtube-channels/:key/anchor` — body `{ url, confirm }`. A pasted video link moves that tab's anchor and does not download the file. An id already in the ledger returns `needsConfirm` with `savedAt` (the ledger `at`) until `confirm` is true. An id that was never saved becomes the anchor immediately and is not marked downloaded. The same id as the current anchor returns `already` and does not rewrite the row.
- `DELETE /api/youtube-channels/:key` — drops that row from the ledger. It does not delete saved mp4 files or the remembered video ids.
- `POST /api/youtube-channels/known` — body `{ ids }`. Returns `{ videos: [{ id, title, at }] }` from the global ledger, at most 40 ids. No yt-dlp. The date is the ledger `at`.
- `POST /api/youtube-channels/:key/concat` — body `{ ids, marks, sharedFolder }`. Joins 2 to 20 mp4s of that one tab. `marks` are the on-screen numbers, where 1 is the newest file in `local`. The output is `Ghep 2-1.mp4` in the channel folder, or the shared folder when that channel has none. A name already used becomes `Ghep 2-1 (2).mp4`. The name has no `[videoId]`, so the channel scanner does not treat it as a download. ffmpeg copies the streams first. If that fails, it scales and pads onto the largest even canvas and re-encodes. Source files stay. The sources together must be at most 16 GiB. This does not take the import slot, does not move the anchor, and does not write the ledger or a receipt.
- `GET /api/youtube-receipts` — `{ items, keepDays: 7 }`. Each item is `{ id, videoId, title, channelKey, saved, at, savedAt }`. A saved row older than 7 days is dropped on read. An unsaved row stays.
- `POST /api/youtube-receipts` — body `{ id, videoId, title, channelKey, holdPath }`. `holdPath` must be an existing file inside `uploads/youtube-import`. The client cannot set `savedPath` here.
- `POST /api/youtube-receipts/:id/copy` — body `{ path }`. Copies the saved file, or the hold file, into that folder and rejects a folder inside the import root. The row becomes saved. Another copy writes a new file and keeps the first `savedAt`.
- `DELETE /api/youtube-receipts/:id` — drops one list row. It does not delete the mp4.
- `DELETE /api/youtube-receipts` — optional query `channelKey`. An empty key drops every row. It does not delete mp4 files.
- `server/youtube-url.js` — allowlist, caps (2 hours, 8 GiB), format selector and `res:` sort, progress parsing. No spawn and no network. A channel URL is still `not_video` here.
- `server/youtube-channel.js` — pure channel URL, flat-playlist read, and the anchor plan. No spawn and no network.
- `server/youtube-channel-store.js` — `uploads/youtube-channels.json`. Video ids and per-tab anchors survive a restart. `filesInFolder` lists mp4s whose names end in ` [videoId].mp4`.
- `server/youtube-concat.js` — pure concat helpers: `localVideos`, `concatRequest`, `concatFileName`, copy and encode args, probe and canvas. No spawn.
- `server/youtube-channels.js` — scan, list, folder, anchor, known-id, concat, and remove handlers.
- `server/youtube-receipts.js` — `uploads/youtube-receipts.json`. Saved rows expire after 7 days. Unsaved rows stay. Clear drops the row and leaves the mp4. A saved row includes `folder`, the directory of the saved mp4. A second save of the same video on the same channel updates that row and adds `redownloads` instead of a new row.
- `server/youtube-import.js` — `createYoutubeImport`, `uniqueStreamBlock`. Children set `job.ffmpeg` and `job.killTree` so cancel kills the process tree. If yt-dlp is missing, the status check downloads the official binary into `.youtube-bin/` (pip `--user` only if that download fails). v1 does not read cookies. Optional `channelKey` on the import body is stored on the job and is not part of the 201 body.
- UI: `src/components/YoutubeImportBox.tsx` and `src/components/YoutubeChannelPanel.tsx`, the YouTube tab in `src/ghostforge-app.tsx`. The panel stays mounted and is hidden on other tabs, so the queue keeps running after leaving YouTube. Waiting URLs live in `sessionStorage` key `gf_youtube_batch` (max 30). Each item stores its save folder and destination. The server slot is still one download; the UI starts the next URL when the current stream finishes. With no saved destination, the default is “Chỉ lưu file”. Waiting rows and the download list show the YouTube poster `https://i.ytimg.com/vi/<id>/mqdefault.jpg`. The download list is the receipt file, not the browser session, and it shows only the channel that is selected. A saved row says đã lưu and Mở thư mục opens the folder stored for that mp4. An unsaved row says chưa lưu. Quét lại shows “Đang quét, vui lòng chờ.” and then “Đã quét xong.” The channel list is a fixed-height column. The selected channel shows the anchor poster and name, then “N cũ hơn” and “N mới hơn” once an anchor exists. With no anchor the count is “Tải N mới nhất”. A selected channel that already has an anchor scans on its own. An id already in the ledger asks for the date before a second download from a paste or a channel count. Tải lại on a receipt row downloads that video again into the channel folder, or the shared folder when the channel has none, and does not ask. Its destination is save only. Sending the file to Unique, Edit, or Reframe starts that idle tab. Unique uses the preset stored on the queued item, then the preset saved for that channel, then the switches already open. Edit uses the profile saved for that channel when one exists. The anchor name, each receipt row, and each concat number's “mở” open `https://www.youtube.com/watch?v=<id>` in a new tab. An id that is not 11 characters is not a link. Save, clear, and the number itself stay buttons. Under the selected channel, Ghép joins the clicked numbers. The next step is Chỉ lưu file, Unique, or Edit. A Unique preset or the open Edit switches can be stored on that channel, or on a named chain, in `gf_youtube_concat`. The channel copy wins. Gắn preset cho chuỗi asks before replacing a preset already stored under that name. A saved attach shows Đã gắn preset riêng or Đã gắn preset chuỗi. Each channel in the list, and the line under Ghép, says Preset riêng or Preset chuỗi. Ghép does not need a private folder: the file goes to that folder when it exists, and to the shared folder otherwise. Unique after Ghép uses the preset on the row, then the saved channel preset, and starts at once. A missing preset starts the open panel. Edit after Ghép uses the saved profile and starts at once. Edit stores switches and the prompt only. API keys stay on the live panel.

### TikTok trend finder
- `GET /api/videos/hashtag?tag=<name>` — optional direct TikTokApi lookup through `server/tiktok-hashtag-search.js` and `tiktok_hashtag_search.py`. The Trends panel does not call it because TikTok blocks automated requests on this host.
- `scripts/tiktok-api-session.py` — interactive TikTok.com session setup; saves ignored `.tiktok-api-session/storage-state.json` for the hashtag bridge.
- `GET /api/trends/config` — countries, periods (7/30 days) and minimum-view steps for the Trends tab.
- `GET /api/trends?region=VN&period=30&minViews=100000` — trending hashtags, top videos and caption keywords. Read-only, no job/SSE, results cached ~10 min.
- Filters: `minViews`, `maxViews` (view band), `minDuration` (seconds, via ffprobe), `limit` (video pool, max 100). The panel pages the returned videos 20 at a time.
- Provider: `server/tiktok-trends.js` (free TikTok Creative Center source; no login). The panel is `src/components/TrendsPanel.tsx`; the tab is registered in `src/ghostforge-app.tsx` as `appTab === 'trends'`.
- Logged out, the source is a teaser: 3 hashtags and 4 videos per country/period, and its video list only covers US, JP, VN, TH, ID; the response carries that in `limitations`. Logged in it returns 20 hashtags and up to 100 videos (the page embeds 20; the list API adds the rest).
- Video rows come from `/CreativeOne/Report/CreativeCenterGetTopContentsList` (US: `ads.us.tiktok.com`, others: `ads.tiktok.com`), with `periodDimension` 3/5 and a `periodEndTimestamp` read from the page's `videoOverview`. See VALIDATION.md.
- That API returns `itemID` as an unquoted number; `quoteBigIds` quotes long `*ID` fields before `JSON.parse` so the 19-digit id (and therefore every watch URL) stays intact.
- Video length is not in the payload; `ffprobeDuration` reads it from the embedded signed CDN mp4 link and the service caches it per video id. `minDuration` (seconds) filters on it.
- `server/tiktok-session.js` — reads the `ads.tiktok.com` cookies out of the repo-owned Chrome profile (`.tiktok-session/`, gitignored) over the DevTools protocol, because Chrome encrypts its cookie store; cached 6 h. `scripts/tiktok-session.mjs login|check` drives that profile interactively.

### Unique pipeline
Start at `POST /api/upload`, then `GET /api/stream/:jobId`. A disk source (the YouTube import file) starts at `POST /api/unique/job-local` instead, with `keepInput: true`, then the same stream. Both set `uniqueRun`. That route does not set `kind`.
`POST /api/unique/pause/:jobId` with `{ paused: true|false }` freezes or continues that Unique job's current child (`NtSuspendProcess` / `NtResumeProcess` on Windows). It does not cancel the clip. A job that is not `uniqueRun` is left alone. The next Unique child spawned while the flag is set is frozen too.
Named Unique presets live in the browser (`gf_named_presets`, `src/lib/unique-presets.js`). The built-in full-frame / barred / max select is gone. A preset stores the switches the operator set, including encoder, and does not store a seed. The saved names are one dropdown. Choosing a name applies it and does not start a run. Sửa loads that preset onto the panel. Lưu lại overwrites the same id and leaves edit mode, so Lưu lại and Hủy go away. A failed save stays in edit mode. A toast confirms Tạo preset and Lưu lại. A name already used by another preset is refused and the saved preset stays. Hủy leaves the saved preset as it was. Edit, Reframe, and YouTube each pick one preset when sending to Unique. If Unique is idle, that send applies the preset and starts the queue. If Unique is already running, the clip waits and keeps the settings of the run already started. The Unique log's first line names that preset. No preset says the open panel was used. A clip sent from YouTube keeps that tab's preset name on the finished row (`youtubeHandoffNote`).
`enableSmooth` and `enableCaptions` ride on the existing upload body. Both default off. Off skips that step. The order is Smooth (`server/unique-extra.js` `smoothPlan`; full HD uses `smoothFilterGraph`, a smaller frame or AI uses the binary in `tools/realesrgan/`). While that model writes frames, `smoothFrameProgress` moves the Làm mịn bar. Then Unique, then PGD, then captions (`caption_words.py` plus `googleSttWords` with the detected language, `alignCaptionWords`). Caption place is middle or bottom (`captionAnchor`). The bottom line sits 10% in from the edge. Middle stays centred. An old top place is stored as middle. Cancel releases the Unique run immediately, so the next clip sent from YouTube can start. Unique filters and the Edit `en-US` call are unchanged. `DELETE /api/job/:jobId` also removes `<jobId>_smooth.mp4`, `<jobId>_smooth_work/`, and the caption sidecars.
A Unique command past `WINDOWS_COMMAND_BUDGET` (24000) keeps the same video filter and the same per-second `atempo` branches. FFmpeg 9 here has no `-filter_script`. The audio head is written once, the branches run in chunks from `chunkTempoBranches`, then the video and audio are muxed. Shorter clips stay one FFmpeg command.
Related output lifecycle: `/api/compare/:jobId/:kind`, `/api/download/:jobId`, `/api/job/:jobId`, `/api/cancel/:jobId`. `DELETE /api/job/:jobId` also removes `<jobId>_aspill_*`.
A finished Unique render is also written to `uploads/unique-hold.json` by `server/unique-hold.js` before the `done` event. `GET /api/unique/held` is what the Unique screen loads on startup. `POST /api/unique/held/:jobId` updates the display name. `DELETE /api/unique/held/:jobId` drops one record without deleting the mp4. Save (`POST /api/export-copy`) drops the record after the copy. Remove (`DELETE /api/job/:jobId`) drops the record and the file. On boot the server puts those jobs back so download, compare and export work. Their stream is already finished, so opening it does not encode again. Reframe outputs are not scanned. A finished Edit part is written to `uploads/edit-hold.json` by `server/edit-hold.js` before `part-done`, and only when that mp4 already exists. `GET /api/edit/held` fills the cut list on startup. Save drops that part. Clear calls `DELETE /api/edit/held/:jobId` and drops the row without deleting the mp4. The uploads folder is not scanned.
Do not assume Unique behavior when changing Edit/Reframe. A successful Unique encode still unlinks `job.inputPath` before `done`; `keepInput` only stops `DELETE /api/job/:jobId` from doing that. The YouTube UI then deletes the import directory.

### Edit pipeline
Start at `POST /api/edit/job-local` or `POST /api/edit/job`, then `GET /api/edit/stream/:jobId`. When every Gemini key is out of daily quota, the stream emits `gemini-keys` and waits. `POST /api/edit/gemini-keys/:jobId` with `{ apiKeys }` resumes that same job. `POST /api/edit/log-fallback-parts` reads a saved log and lists failed part timestamps for a source filename. `POST /api/edit/part-test` accepts `sourcePath` plus those timestamps and renders only that excerpt.
Important symbols:
- `runSerializedVertexPost`, `waitForVertexCooldown`, `waitQuota` — Vertex quota/cooldown scheduling.
- `runEditEncode` — Edit-specific encode execution/fallback.
- `padTikTokClip`, `mixFrameClip` — SML composition/framing (contain/fill).
- `composeFocusClip` — default general-content 9:16 framing (`framingStyle=focus`): subject crop with hold/pan, optional corner window and top/bottom split; graph from `focusFrameGraph`. Before the gates it may call `local_layout_scan.py` and `applyFocusLayout` so a portrait graphic beside a person, exactly two people, two objects on a dark canvas, two ink drawings on a light page, or two round objects become a split without another API call. A round-object split, a two-person split, and an arms-on-the-table split skip the 0.85 look-alike drop. Phones, side pairs and ink drawings still use it.
- `geminiUploadVideo`, `geminiGeneratePlan`, `geminiDeleteFile` — Gemini Files/API plan path.
- `getAdcAuth`, `shrinkProxyForVertex`, `vertexGeneratePlan`, `vertexJsonVideo` — Vertex path.
- `googleSttWords` — Google STT integration.
- `runLocalDiarization` — local diarization integration.
- `cutEditClip` — final edit clip creation.

Targeted part testing:
- `GET /api/edit/part-test/history`
- `POST /api/edit/part-test`
- `GET /api/edit/part-test/stream/:jobId`
- `targetedPartRanges`

Global coverage before Detail:
- `server/edit-content-coverage.js`: `globalCoverageGuidance`, `applyGlobalCoveragePolicy` — same-call exclusion evidence and automatic keep-uncertain reconciliation; replaces manual tail review/routes.
- `server/edit-run-report.js`: `createEditRunReport` — aggregate existing stage/429 diagnostics before terminal SSE.
- `src/ghostforge-app.tsx`: `startEdit` per-source elapsed summary; `addLog` keeps a full export per function (`unique`, `edit`, `reframe`, `youtube`) and a bounded on-screen list for that function only. `src/lib/log-channels.js` (`logChannel`, `appendDisplayLog`) chooses the panel from the line tag. Starting Unique clears only the Unique panel.
- `server/local-detail.js`: private Ollama lifecycle, Qwen3-VL multimodal request, visual-only Detail prompt and persisted-range selection for experimental 30/60s TEST.
- `uploads/local-detail-test-range.json`: last local TEST source/range metadata so reruns reuse the same excerpt; select “Đổi đoạn ngẫu nhiên” to replace it.

## Extracted backend modules
- `server/jobs.js` — job registry, SSE history/subscribers, abort/cancel. `abortJob` uses `planChildKill`: a job with `killTree` kills the process tree; every other job stays a single `SIGKILL` on `job.ffmpeg`.
- `server/process.js` — generic child process runner. `runProcess` accepts `{ onSpawn, onStdout, onStderr }` and still forwards spawn options, including `timeout`. `killProcessTree` is `taskkill /T /F` on Windows and `kill(-pid)` on POSIX. `planUniquePause` decides suspend/resume for a `uniqueRun` job only. `setProcessSuspended` calls `NtSuspendProcess` / `NtResumeProcess` through PowerShell on Windows.
- `server/save-dir.js` — persisted save-directory store.
- `server/unique-hold.js` — Unique renders that finished and were not saved yet (`remember`, `rename`, `forget`, `list`, `rehydrate`). File: `uploads/unique-hold.json`. No scan of other pipelines' outputs.
- `server/gemini-secrets.js` — persisted Gemini key/model store (plain text in `uploads/gemini-keys.json`, path overridable by `GHOSTFORGE_SECRETS_FILE`). Pure file I/O; never logs values.
- `server/detail-models.js` — Detail model ordering for the Gemini-API path (`orderDetailModels`, modes `safe`/`quality`/`only`) and the 10-minute per-model overload cache (`createOverloadCache`). Pure; unit tested in `tests/detail-models.test.js`.
- `server/edit-qa.js` — post-render quality score for one Edit part (`buildEditQaReport`, `QA_WEIGHTS`): subject-inside-crop, empty frames, hold length, edge pinning, plan coverage → 0-100 + warnings. Pure; unit tested in `tests/edit-qa.test.js`. History lives in `uploads/edit-qa-history.json`, read by `GET /api/edit/qa-history`. That response includes `catalog`: one row per source video, latest row per part, for the Edit replay list.
- `server/qa-tune.js` — turns that history into one decision without human labels: `suggestDetailConfig` (needs >= 12 parts per mode and a >= 5 point gap) and `replayCatalog` (videos, not a flat 500-row list). Pure; unit tested in `tests/qa-tune.test.js`. The manual self-test A/B routes were removed on 2026-10-04.
- `server/gemini-cost.js` — Gemini API-key spend for one Edit job: `usageFromMetadata` (cached prompt tokens split out, thinking counted as output), `usageCostUsd`/`usdToVnd`, `summarizeCost`, `formatVnd`, `GEMINI_PRICE_TABLE` and `VND_PER_USD`. Pure; unit tested in `tests/gemini-cost.test.js`. Fed by `job.geminiUsage`, which `recordGeminiUsage` fills in `ghostforge-server.js` on every successful API-key call; the result is `done.report.geminiCost` and the `[EDIT] Tiền Gemini API (token thật)` log line. Vertex spend is not counted.
- `server/topic-profiles.js` — topic routing: 8 topic workflows (cops, animals, podcast, sports, gameplay, reaction, product, story) + generic, `normalizeTopic`/`topicProfile`/`resolveTopic`/`topicClassifierPrompt`, `TOPIC_MIN_CONFIDENCE` 0.6. Pure; unit tested in `tests/topic-profiles.test.js`. Applied to the global plan and the per-part Detail prompt; a pinned topic comes from the Edit tab (`topicPin`).
- `server/editor-plan.js` — pure plan parsing/normalization, framing/speaker helpers. Framing modes: `contain`/`fill` (SML) and `focus`/`pip`/`split` (general 9:16, see `FRAME_MODES`). Prompts: `focusEditorPrompt` / `focusDetailPrompt` (default path), `generalEditorPrompt` / `generalGlancePrompt`, `editorSysPrompt` (SML). Prefer unit tests here for plan logic.
- `server/ffmpeg-expressions.js` — pure FFmpeg expression/graph builders: `balancedSum`, and the focus 9:16 graph (`fitCropBox`, `zoomCropBox`, `holdSnapExpr`, `holdSnapScript`, `enableExpr`, `focusFrameGraph`) used by `composeFocusClip`. A focus window is a 3:4 crop centred on a blurred frame. Split halves stay full-frame. A graph past `WINDOWS_COMMAND_BUDGET` (24000) returns a short `sendcmd` filter plus the script text; the caller writes that file. A split window with `panelW` pads that half to the panel width; other halves keep the shared zoom box. No I/O.
- `server/focus-layout.js` — `applyFocusLayout`, `panelFaceSplits`, `twoPersonSplits`, `armSplits`, `sidePairSplits`, `keepsLookAlikeSplit`. Pure. Turns a `local_layout_scan.py` sample list into focus/split windows, lone-panel aim points, a centre aim for a still empty card after a cut, and focus aims that follow one sharp face. A narrow box cut by the frame is not a half. Two people may drift by 0.2; other pairs still break at 0.1. Two body boxes count only when that frame has no face. Two body boxes whose tops sit in the top fifth are arms on a table and become their own split (`detector: hai tay`), aimed at the body boxes, so a knuckle detected as a face does not move the cameras or extend the seated pair. Exactly two real faces at least 0.30 apart open a split; a face pair at least 0.29 apart only continues one that already opened when each face has barely moved. Body boxes still need 0.35, and that gate is unchanged. That split and the arms split skip the 0.85 look-alike drop. A wide product card just under a second long still splits when the next sample is the cut, and the same close-up one sample earlier starts that split. A face narrower than 0.06 does not keep a model split. No I/O.
- `local_layout_scan.py` — YuNet faces (with a sharpness score), YOLO person boxes, portrait-panel edges, a dark-canvas side pair, and the frame-to-frame change for one cut part. When that pair finds nothing and no real face (width at least 0.06) is present, it also reports two ink drawings on a light page or two round objects (`pairKind` `ink` or `round`). One real face beside a wide dark board on a bright page is also a side pair. A phone whose far edge is covered still counts when the open edge matches a clean ad and the strict pair missed. Called by `composeFocusClip` unless `GHOSTFORGE_LOCAL_LAYOUT=0`. Samples past the plan are aimed by `applyFocusLayout` with the same face rule.
- `server/gemini-detail-quota.js` — reads Gemini `generateContent` error details, tells a per-day request quota from a per-minute limit, computes the next Pacific midnight, and tracks that cap per API key.
- `server/edit-log-replay.js` — reads a saved Edit log and returns the source-time ranges of parts that fell back to the Global plan.
- `server/local-listen-map.js` — maps diarization evidence to speech/speaker turns.
- `server/google-stt-retry.js` — partial/retry behavior for STT chunks.
- `server/ffmpeg-diagnostics.js` — extracts useful FFmpeg errors.
- `server/youtube-url.js` — pure YouTube URL, cap, format-sort, and progress helpers for the import. No I/O.
- `server/youtube-channel.js` — pure channel tab URL, flat playlist parse, and `planChannelBatch`. No I/O.
- `server/youtube-channel-store.js` — ledger for channel rows and downloaded video ids.
- `server/youtube-channels.js` — channel scan, folder, known-id, concat, and pasted-anchor routes. The scan does not take the import slot. A pasted link does not call yt-dlp. The next scan fills in the title when that id is still in the window. Concat does not call yt-dlp either.
- `server/youtube-receipts.js` — disk list of downloaded YouTube videos. `uploads/youtube-receipts.json`.
- `server/youtube-import.js` — YouTube import job factory and the Unique-stream guard `uniqueStreamBlock`. A successful save notes a receipt.

- `server/perceptual-hash.js` — pure helpers for the Unique estimate and its quality guard: dHash (17x16, 256-bit), DCT pHash (63-bit), block-wise dHash grid, row-step/seam profile (`rowStepProfile`, `seamVerdict`) and the luma-delta helpers. No I/O. `src/ghostforge-app.tsx` imports the two verdict helpers from here so the guard rule has one definition and a unit test.
- `server/audio-profile.js` — pure audio measurement for the Unique panel: `rmsDb`, `segmentRmsDb` (loudness per second), `fftPowerSpectrum`, `bandProfileOverTime` (three-band energy per second), `alignSeries`/`compareSeries` (source vs render at the same content time through the retime factor) and `analyzeAudioPair`, which returns level delta + drift, per-band delta + drift and a max-sample-jump click ratio. No I/O: the caller pipes mono 16 kHz PCM.
- `server/harsh-scale.js` — pure filter string for the post-compress proxy: libx264 crf 30, long side at most 720, never upscaled. No I/O.
- `server/tempo-curve.js` — pure Unique tempo curve: `shapeForGain`, `outputTimeAt`, `tempoCurve`. Same slice speeds for video `setpts` and audio `atempo`. No I/O.

## Python
- `local_listen_diarize.py` — local speaker diarization; uses a separate diarization Python environment by default.
- `pgd_server.py` — long-lived PGD process. Loads ViT-B-32 once and accepts attack jobs plus `sim` / `vram` / `unload` on stdin. `runPgdClip` uses it first and falls back to `pgd_clip.py`.
- `pgd_clip.py` — PGD/OpenCLIP/PyTorch processing: CLIP ViT-B-32 + EOT jpeg/resize attack on CUDA, loss and write path both on the pool-4 residual, no full-frame carrier, then the write-out pass. `--enc-args` (JSON array of FFmpeg video encoder args) and `--enc-label` come from the server, which resolves the operator's Encoder choice and smoke-tests it; empty/malformed args fall back to `libx264 crf 16`. `--batch` (default 8) attacks that many frames per forward/backward call and halves itself on CUDA OOM, retrying the same frames. Decode fills a frame queue and the previous group is written while the current group is attacked. eps, steps and phase are unchanged. Opt-in experiment flags that default to the shipped behaviour: `--eot-mode jpeg|codec|ladder|mix` (default `jpeg`), `--pool-size` (default 4), `--amp off|bf16|fp16` (default `off`), `--adaptive-skip` (default 0), `--phash-loss` (default 0, measured not worth it) and `--compile` (traces once and falls back to eager; Windows has no C compiler here, so it stays eager). `load_clip_pack` reads a local checkpoint when `GHOSTFORGE_CLIP_WEIGHTS` is set, otherwise it uses the Hugging Face hub. `runPgdClip` and `measureClipSim` share `withGpuExclusive`, so only one of those CUDA CLIP users runs at a time.
- `clip_sim.py` — semantic measurement only (no attack): decodes 12 frames at 3 fps from two files, embeds them with ViT-B-32 and prints `CLIPSIM {"meanClipSim":...}` for the Unique result panel. Called by `measureClipSim` in `ghostforge-server.js`; failure/timeout is a logged skip, never a job failure.
- `clip_sim_server.py` — long-lived CLIP helper for the same measurement: loads ViT-B-32 once and answers `{"id","a","b","frames"}` JSON lines on stdin/stdout, plus `{"cmd":"vram"}` (free/total VRAM) and `{"cmd":"unload"}` (drop the weights, keep the process, reload lazily) which the server uses to share the card with a PGD pass. Started lazily by `ensureClipWorker` in `ghostforge-server.js` and abandoned in favour of `clip_sim.py` if it fails. Imports the frame extraction from `clip_sim.py` so both use one method.
- `requirements-pgd.txt` — PGD Python dependencies.

## Frontend
`src/ghostforge-app.tsx` is still the main stateful UI. The open tab is stored in `localStorage` key `gf_app_tab` and comes back on refresh. Sending a clip to Unique still switches to that tab.
Useful entry symbols:
- `runOneEdit`, `startEdit`, `cancelEdit`, `testEditPart` — Edit.
- `runOneReframe`, `startReframe`, `cancelReframe` — Reframe.
- `processOneFile`, `startProcessing`, `cancelProcessing` — Unique. `processOneFile` posts `POST /api/unique/job-local` when `clip.localPath` is set and does not build `FormData` on that branch. On mount the Unique screen loads `GET /api/unique/held` and shows those unsaved renders in Completed. During a run, `startProcessing` claims the next clip from the live list, so a file added from the drop zone, the picker, or YouTube joins that run.
- `appendYoutubeClip`, `releaseYoutubeImport` — add a downloaded YouTube file when the destination is Unique, Edit, or Reframe, and delete `uploads/youtube-import/<jobId>/` on Unique/Reframe success or on X. Edit success keeps the directory for Test lại. Save-only does not call these. An idle destination starts at once. Unique applies the preset on the queued item, then the preset saved for that channel, then the switches already open. A saved Edit profile is applied only when Edit is idle, and that run keeps the profile it started with. A busy tab keeps the new clip behind the one already running and does not change the panel.
- save/export helpers are in the same file.
